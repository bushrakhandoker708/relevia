# Where Relevia's data goes

This is an inventory of every place the app stores something or sends something over the network, as of 21 November 2026. It exists so that the privacy wording on the site can be checked against the code rather than taken on trust. `tests/data-flows.test.js` fails if a storage key or network call appears in `src/` without being listed here, so the list cannot quietly go out of date.

It was compiled with agent assistance by reading the source and searching it for storage and network calls. It is not a guarantee: a search finds what it was written to find, and third-party libraries (WebLLM, Vercel Analytics, React) were not audited line by line.

## Summary

| What | Where it lives | Leaves the device? | How long | How to remove it |
| --- | --- | --- | --- | --- |
| Chat messages | Memory (the open tab) | No | Until the tab closes | Close the tab, or "Delete all chat history" |
| Saved chats (opt-in) | `localStorage`, `relevia_chat_v2:<random id>` | No | 24 hours, pruned on read and write | "Delete all chat history" in the chat panel |
| Name given in chat | Memory | No | 24 hours or until the tab closes | Same as chat |
| Journal entries, draft, settings, own prompts | Memory only, until the person chooses "Keep on this device"; then `localStorage`: `journalEntries`, `journalDraft`, `journalSettings`, `customPrompts`, with the choice in `journalStorage` | No, unless the person exports a file | Until the tab closes, or no automatic expiry once kept | "Delete everything" in the journal's "Your data" tab |
| Activity counts | `localStorage`, `relevia_activity_v1` | No | No automatic expiry | "Forget them" under the home-page letter |
| Kept affirmations | `localStorage`, `relevia_kept_affirmations_v1` | No | No automatic expiry | "Forget them", or untick on the Affirmations page |
| Visualisation settings and session count | `localStorage`, `visualization-personal-settings`, `visualization-completed-sessions` | No | No automatic expiry | Edit on the page, or clear site data |
| Display preferences | `localStorage`, `relevia_chat_plain`, `relevia_breath_balls` | No | No automatic expiry | Change the setting, or clear site data |
| Visit and letter flags | `sessionStorage`, `relevia_visit_counted`, `relevia_letter_opened` | No | Until the tab closes | Close the tab |
| Model files | Browser Cache Storage, managed by WebLLM | Downloaded from Hugging Face and GitHub | Until the browser evicts them or site data is cleared | Clear site data |
| Page views | Sent by Vercel Analytics | Yes, to Vercel | Vercel's retention | Not controllable in the app |
| Speech | Browser speech synthesis | Depends on the voice (see below) | Not stored by Relevia | Leave voice off |

## Chat

Chat text is generated by a model running in the browser through WebLLM (`src/services/releviaBrain.js`, `src/services/llmWorker.js`). The prompt and the reply do not leave the device. The retired cloud integration in `src/services/groqApi.js` throws if called and is not imported anywhere.

By default a chat is kept in memory only (`src/services/chatStorage.js`). Saving across reloads is a choice in the chat panel. When it is on, turns are written to `localStorage` under `relevia_chat_v2:` plus a random session ID, pruned to the last 24 hours, and capped at 100 rows. If a message matches the crisis or sensitive-content filter, saving is switched off for that whole chat and any saved copy is deleted, because later replies may quote it. Saved copies that contain sensitive text are ignored when read back.

"Delete all chat history" clears every `relevia_chat_v2:` key, the older `relevia_memory_` and `relevia_visits` keys, the legacy IndexedDB database named `relevia`, and the visit flag. It also tells other open tabs to clear their in-memory chats through a `BroadcastChannel` called `relevia-chat-clear`. It does not touch the journal or the activity counts; the journal's "Your data" tab says so.

`src/services/memoryUtils.js` guesses the tone of a chat message to pick a fallback reply when the model is not loaded. The guess is used for that reply and not stored.

## Journal

All journal data is handled by `src/services/journalStore.js`. By default the journal is kept in the page's memory only and is gone when the tab closes; nothing is written to the browser. Saving to the browser's `localStorage` happens only after the person presses "Keep my journal on this device", and that choice is recorded in `journalStorage`. Pressing it again moves everything back into memory and removes the stored keys. A journal stored by an older version is detected and the person is asked whether to keep it on the device. In either mode, entries are saved when the person presses "Save entry", and the draft about 0.7 seconds after typing stops. Every write reports whether it worked, and the page says so when the browser's storage is full or blocked instead of claiming to have saved.

Nothing reads the journal except the journal page. Its contents are not used for personalisation, are not sent to the chat model, and are not analysed. The previous version scored entries for "tone" and "growth"; that was removed, and old entries keep their stored `sentiment` field untouched but it is never shown or used.

Exports are files made in the browser (plain text or a JSON backup). Restoring a backup adds entries that are not already present and never deletes any.

## Activity counts and the home page

`src/services/activity.js` stores counts only: visits, chats started, and for each technique how many times it was opened, started and completed. What "completed" means is defined per technique in `DONE_MEANS`; affirmations have no completion, so none is recorded. No text, timestamps of individual actions, or contents are stored. The home-page letter and "A few words for you" are built from these counts, and the wording distinguishes opening a technique from starting or finishing it, so the site does not claim someone did something they only looked at.

"Forget them" removes `relevia_activity_v1`, `relevia_kept_affirmations_v1` and the visit flag.

## Network requests

| Request | When | Sends |
| --- | --- | --- |
| The site itself, from Vercel | Every visit | What any web request sends: IP address, user agent, requested path |
| Vercel Analytics (`@vercel/analytics`, in `src/App.jsx`) | Every page view | The page path and referrer, to Vercel. No chat or journal content. |
| Model weights and compiled model code | When the chat model loads for the first time, after a short delay or when the chat button is hovered or focused | The model file requests, to Hugging Face and GitHub (WebLLM's default sources). No conversation content. |
| Links to outside sites (Medication, Contact, Resources) | Only when the person follows one | A normal visit to that site |

Fonts are bundled with the site, so there is no Google Fonts request. The app used to open an early connection (`preconnect`) to `vitals.vercel-insights.com`. Nothing used it, since the analytics package posts to the site's own `/_vercel/insights` path, and an early connection still shows the visitor's IP address to that host, so it was removed on 21 November 2026.

## Speech

Reading aloud uses the browser's `speechSynthesis`. Some voices run on the device and some are online voices that send the text to the browser vendor's servers. `src/services/softVoice.js` can tell them apart through `SpeechSynthesisVoice.localService`.

- Chat replies and journal read-aloud use on-device voices only, because the text can contain what the person wrote. If there is no on-device voice, nothing is read.
- Affirmations and visualisation scripts may use online voices, because the text is Relevia's own fixed wording.

Speech is off by default in the chat. Relevia does not use speech recognition.

## Errors

`src/components/ErrorBoundary.jsx` shows a recovery screen when a page crashes. It does not save or send error messages, stack traces or URLs, because they can contain what someone typed. There is no error-reporting service.

## Known gaps

- Journal entries are not encrypted. Anyone using the same browser profile can read them. The journal page says so.
- The visualisation "things to avoid" list is text the person types. It is kept until they edit it or clear site data, and neither "Forget them" nor the chat deletion removes it.
- Vercel Analytics cannot be turned off from inside the app.
- Clearing site data removes everything above, including journal entries, so the journal page recommends exporting a copy.
